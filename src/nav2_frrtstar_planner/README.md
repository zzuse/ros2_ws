RRT* (Liao et al., 2021) is an RRT* variant that gets a much better initial path and faster convergence by exploiting the triangle inequality. It keeps RRT*'s sampling, steering, and rewiring, but replaces the ChooseParent neighbor scan with two new procedures, both now in src/nav2_frrtstar_planner.cpp:

1. FindReachest (nav2_frrtstar_planner.cpp:161) — after steering produces a collision-checked new point, instead of parenting it to the nearest node, the planner climbs the nearest node's ancestor chain and connects directly to the farthest ancestor that still has a collision-free straight line to the new point. A straight line to an ancestor is never longer than the zig-zag through the intermediate tree nodes, so every wiring is immediately shorter than what plain RRT* would produce.

2. CreateNode (dichotomy) (nav2_frrtstar_planner.cpp:175) — by definition, the reachest ancestor's own parent is not visible from the new point, which means an obstacle corner sits between them. A binary search along that tree edge finds the point closest to the corner that can still see the new point, backs off by one costmap cell for clearance, re-verifies the shortcut, and inserts a brand-new node x_create there (its edge to the ancestor is free by construction, since it lies on an existing tree edge). The new point is then wired through x_create, so the path hugs obstacle corners — which is where geometrically shortest paths actually run. The corner node is only accepted when it genuinely lowers cost; otherwise the planner falls back to x_reachest.

The rewire step is kept unchanged from RRT* (F-RRT* retains it), so the tree still converges toward optimal over iterations. Supporting tweaks: tree.reserve doubled since each iteration can now add two nodes (x_create + x_new), and neighbor collection now serves only the rewire step. The goal-connection logic, path backtracking, and interpolation are untouched, and neighbor_radius still controls the rewire range.

One behavioral note for your maps: because paths now hug corners at only ~1 cell of extra clearance beyond the inscribed-obstacle threshold, paths will run tighter past obstacles than the old RRT* did. If the fishcar clips corners in practice, the easy knob is the back-off in createNode (currently clearance = costmap_->getResolution() — raise it to 2–3× resolution or make it a parameter).
